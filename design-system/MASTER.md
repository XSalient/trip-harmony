# MASTER — Trip Harmony Design System

Global source of truth. A file in `pages/` overrides this document for its own
screen; absent one, this governs.

Built with the `ui-ux-pro-max` skill. Style direction: **warm editorial travel
with dimensional depth** — photo-led warm-neutral ground, one confident brand
hue, generous radii, a 4-level elevation scale, and spring-based motion.
Blur is used only where it carries meaning (sticky header, floating tab bar,
sheet scrims), never as decoration.

---

## 1. Non-negotiables

Ordered by impact. 1–3 are blocking; a screen is not "done" until they hold.

| #   | Rule                                                                  | Check                                         |
| --- | --------------------------------------------------------------------- | --------------------------------------------- |
| 1   | Text contrast ≥ 4.5:1; UI/graphic contrast ≥ 3:1 — **in both themes** | `cd design-system && python verify_tokens.py` |
| 2   | Touch targets ≥ 44×44 px, ≥ 8 px apart                                | no `h-8`/`h-9` on anything tappable           |
| 3   | Safe areas respected top and bottom; pinch-zoom never disabled        | `viewport-fit=cover`, no `maximum-scale`      |
| 4   | Semantic tokens only — no raw Tailwind palette classes                | grep guard in §11                             |
| 5   | `min-h-dvh`, never `min-h-screen`                                     | grep guard in §11                             |
| 6   | Colour is never the sole carrier of meaning                           | pair with icon or text                        |
| 7   | Every animation respects `prefers-reduced-motion`                     | §7                                            |
| 8   | SVG icons only (Lucide) — never emoji as an icon                      | §8                                            |

### 2.2 Status scale

Four families, each with five members: base, `-foreground` (on base), `-soft`
(tinted surface), `-on-soft`, `-border`.

| Family      | Hue  | Light base                        | Dark base                 | Means                                   |
| ----------- | ---- | --------------------------------- | ------------------------- | --------------------------------------- |
| `--success` | 152  | `oklch(0.524 0.130 152)` #157E42  | `oklch(0.720 0.114 152)`  | Locked, consensus reached, a "Yes" vote |
| `--warning` | 75   | `oklch(0.541 0.140 75)` #9D5F00   | `oklch(0.720 0.123 75)`   | Pending votes, approaching budget limit |
| `--danger`  | 27.3 | `oklch(0.555 0.205 27.3)` #D02525 | `oklch(0.720 0.180 27.3)` | A "No"/veto vote, over budget           |
| `--info`    | 240  | `oklch(0.527 0.150 240)` #0072B7  | `oklch(0.720 0.132 240)`  | Invites, neutral notices                |

> **`--destructive` vs `--danger` — the most likely source of drift.**
> `--destructive` is a destructive **action** (a Delete button, the
> `ui/button` destructive variant). `--danger` is a **status** (a veto vote, an
> over-budget figure). Different hues, different dark-mode lightness. Never
> substitute one for the other.

### 2.3 Category ramp

Six hues for _taxonomy_, never for state: budget categories, notification
types, itinerary item types. Same five-member shape as the status families.

| Token     | Hue | Light base | Typical use            |
| --------- | --- | ---------- | ---------------------- |
| `--cat-1` | 259 | #386CBE    | Accommodation / invite |
| `--cat-2` | 25  | #B44945    | Food                   |
| `--cat-3` | 152 | #007F3E    | Activities             |
| `--cat-4` | 300 | #7E5BB5    | Vote request           |
| `--cat-5` | 200 | #007A84    | Transport              |
| `--cat-6` | 95  | #876A00    | Other / misc           |

Base lightness is solved so that **two** things hold at once in light mode:
white text on the base reads at ≥4.5:1 (base used as a solid fill), _and_ the
base used as text inside its own `-soft` surface also reads at ≥4.5:1. The
second constraint is easy to miss and was caught by `verify_tokens.py` — a
`text-warning` label inside a `bg-warning-soft` card is a pattern the UI
produces constantly.

### 2.4 Rules of use

- **Status tone is applied through a component's `tone` prop** — `StatusPill`,
  `VoteControl`, `StatCard`, `SectionCard`. Never write `text-success` on
  arbitrary markup; §11's guard enforces this outside `components/harmony/`.
- Dark values are **desaturated tonal variants, not inversions**. Never derive
  dark from light by flipping lightness.
- Every new colour is added to `tokens.py` and must pass its check — not typed
  straight into a component.

## 3. Typography

Two families. Body stays Inter (already loaded, better for dense UI); headings
get Plus Jakarta Sans, which the skill's `typography.csv` recommends for
exactly this product shape.

| Role             | Family            | Weights            |
| ---------------- | ----------------- | ------------------ |
| `--font-display` | Plus Jakarta Sans | 600, 700, 800      |
| `--font-sans`    | Inter             | 400, 500, 600, 700 |

Loaded via preconnect + `display=swap`. Never render-blocking.

### Scale

| Step       | Size / line-height | Weight      | Use                                       |
| ---------- | ------------------ | ----------- | ----------------------------------------- |
| `display`  | 32 / 1.15          | 800 display | Landing hero only                         |
| `title-lg` | 24 / 1.25          | 700 display | Screen large-title                        |
| `title`    | 20 / 1.3           | 700 display | Section headings                          |
| `subtitle` | 17 / 1.35          | 600 display | Card titles                               |
| `body`     | 16 / 1.55          | 400 sans    | Default — **never below 16 px on mobile** |
| `body-sm`  | 14 / 1.5           | 400 sans    | Secondary text                            |
| `label`    | 13 / 1.4           | 500 sans    | Chips, tab labels, meta                   |
| `caption`  | 12 / 1.35          | 500 sans    | Timestamps only. Never body copy          |

- Body ≥ 16 px is **load-bearing**: it is what stops iOS zooming on input focus
  once `maximum-scale=1` is removed. Inputs and textareas must be ≥ 16 px.
- `font-variant-numeric: tabular-nums` on every count, price, tally, date range
  and timer, so numbers do not reflow as they change.
- Line length 35–60 characters on mobile.
- Prefer wrapping to truncation. Where truncation is unavoidable the full value
  must stay reachable.

## 4. Spacing, radius, elevation

**Spacing** — 4 px base. Only these steps: 4, 8, 12, 16, 20, 24, 32, 40, 48.
Rhythm is 16 inside a card, 24 between cards, 32 between sections.

**Radius** — `--radius: 1rem`.

| Token          | Value  | Use                              |
| -------------- | ------ | -------------------------------- |
| `--radius-sm`  | 8px    | Chips, badges, inputs            |
| `--radius-md`  | 12px   | Buttons, small tiles             |
| `--radius-lg`  | 16px   | Cards                            |
| `--radius-xl`  | 20px   | Feature cards, media             |
| `--radius-2xl` | 28px   | Bottom sheets (top corners only) |
| pill           | 9999px | Tab bar, FAB, vote pills         |

**Elevation** — 4 levels, from the skill's `dimensional-layering` entry. Dark
mode reduces shadow and leans on surface lightness instead.

| Token           | Light                           | Role                      |
| --------------- | ------------------------------- | ------------------------- |
| `--elevation-1` | `0 1px 3px rgb(0 0 0 / 0.08)`   | Resting card              |
| `--elevation-2` | `0 4px 6px rgb(0 0 0 / 0.10)`   | Raised card, pressed FAB  |
| `--elevation-3` | `0 10px 20px rgb(0 0 0 / 0.10)` | Floating tab bar, popover |
| `--elevation-4` | `0 20px 40px rgb(0 0 0 / 0.15)` | Sheet, modal              |

One elevation per layer. Never mix arbitrary shadow values.

## 5. Layout

- Mobile-first. Breakpoints 375 / 390 / 768 / 1024 / 1440; primary target 390×844.
- Content column `max-w-2xl` on mobile and tablet; at ≥1024 `PageGrid` takes
  over (1 column below `lg`, 2 above). **Every screen composes its sections as
  `PageGrid` children even though it is a no-op on mobile** — that is what keeps
  the desktop phase tuning rather than surgery.
- Root containers use `min-h-dvh`, never `min-h-screen`.
- The sticky header pads with `env(safe-area-inset-top)`; the floating tab bar
  and any sticky action bar pad with `env(safe-area-inset-bottom)`.
- Scroll containers reserve `--nav-height` plus the bottom inset, so nothing
  hides behind the tab bar.
- No horizontal scroll at any width. Wide content (tables, long chip rows)
  scrolls inside its own `overflow-x-auto`, never the page.

### Vote scales

There are exactly **two** wire vocabularies; all six call sites render the same
three labels and differ only in icon.

```
AVAILABILITY_SCALE   "available" | "maybe" | "unavailable"    Dates
PREFERENCE_SCALE     "love"      | "fine"  | "veto"           Destinations, Stays, Vibe
```

Both map onto a shared `VoteStance` of `up | mid | down`, labelled
Yes / Maybe / No, weighted +2 / +1 / −3. `VoteControl` decides internally
whether a tap is an unvote (`value === wire`) — call sites must not.

### BottomSheet

Renders `ui/drawer` (vaul) below `md` and `ui/dialog` at or above it.
**Never switch variant while open** — React remounts and child state is lost.
Every form keeps its state at page level, so a remount is harmless; keep it
that way.

## 7. Motion

Uses framer-motion (already a dependency, previously unused).

| Token           | Value                                             | Use                         |
| --------------- | ------------------------------------------------- | --------------------------- |
| `--motion-fast` | 150ms                                             | Press, hover, chip toggle   |
| `--motion-base` | 220ms                                             | Enter, expand, fade         |
| `--motion-slow` | 320ms                                             | Sheet, page transition      |
| `--ease-out`    | `cubic-bezier(0.16, 1, 0.3, 1)`                   | Entering                    |
| `--ease-in`     | `cubic-bezier(0.7, 0, 0.84, 0)`                   | Exiting                     |
| spring          | `{ type: "spring", stiffness: 400, damping: 32 }` | Sheets, drag, vote feedback |

- Exit runs at about 65% of enter duration.
- List items stagger 30–50 ms each; cap the stagger at 8 items.
- Press feedback is `scale: 0.97` — never a layout-shifting transform.
- Animate `transform` and `opacity` only.
- Motion must express cause and effect. Decorative animation is a defect.
- Animations are interruptible and never block input.
- Everything sits behind `prefers-reduced-motion`, which reduces to a plain
  opacity fade or to nothing.

## 8. Icons

Lucide only, one family throughout. Sizes are tokens: `icon-sm` 16, `icon-md`
20, `icon-lg` 24. Stroke width 2, or 2.5 for an active nav item. Icons align to
the text baseline. An icon-only control needs an `aria-label` and a ≥44 px hit
area. **Emoji are never icons** — including the heart/check/cross glyphs
currently used for vote tallies.

---

## 9. States

Every interactive element defines all six: default, hover, focus-visible,
pressed, disabled, loading.

- Focus ring: 2 px `--ring` with a 2 px offset. Never removed.
- Disabled: 50% opacity, `cursor-not-allowed`, a real `disabled`/`aria-disabled`.
- Loading: skeleton for anything over 300 ms; a button firing an async action
  disables itself and shows a spinner.
- Pressed feedback appears within 100 ms.
- Read-only is visually distinct from disabled.

---

## 10. Forms and feedback

- A visible label on every field. The placeholder is never the label.
- Helper text is persistent, below the field.
- Validate on blur, not on keystroke. Errors sit below the field, carry an icon
  as well as text, and state both cause and fix.
- After a failed submit, focus moves to the first invalid field.
- Semantic input types so the mobile keyboard matches (`email`, `tel`, numeric).
- Destructive actions confirm first and are visually separated from primary
  actions.
- Toasts: `top-center` (they must clear the bottom nav), auto-dismiss 3–5 s,
  `aria-live="polite"`, and they never steal focus.
- A sheet with unsaved changes confirms before dismissing.

## 11. Grep guards

Run before calling any phase done. All four should return nothing.

```bash
grep -rE '\b(bg|text|border|ring|from|to|via|fill|stroke)-(red|orange|amber|yellow|green|blue|indigo|purple|pink|slate|gray|zinc)-[0-9]' client/src
```

```bash
grep -rn 'min-h-screen\|h-screen' client/src
```

```bash
grep -rnE 'className="[^"]*\b(h-8|h-9)\b' client/src/pages
```

```bash
grep -rn 'text-success\|text-warning\|text-danger\|text-info' client/src/pages
```

## 12. Anti-patterns

- Emoji as icons; mixed icon families; mixed stroke widths.
- Raw hex or Tailwind palette classes in components.
- Colour as the only signal.
- Removing focus rings.
- Placeholder-as-label.
- Truncation with no route to the full value.
- Centred modals on mobile where a sheet belongs.
- Decorative blur, decorative animation, decorative parallax.
- Hover-dependent interactions.
- Deriving dark mode by inverting light values.
- Bottom-nav entries that are actions rather than destinations.
